# P2-8 — B-2 판정 GO 3건: 줌 셀-캐시 + prepare dirty-skip + serialize 스트리밍 (2026-08-10)

B-2 판정표 (§3) GO 3건의 이행. **절대치는 이 VM(claw) 참고치, 유효한 것은
비중·배율** (P2-0 §0 동일 주의). 전/후 실측은 bench-o3 FREE 20스레드
3런 중앙값, 매 런 own-v1 canonical 판정. l09/DAG 절대치는 판정에 쓰지
않는다 (B-2 §5 함정 — 이 VM 에서 l09 cpu-sum 신뢰 구간 2.8x).

## TL;DR

- **FREE gen wall 2092.3 → 1829.7 ms (-12.6%, 청크당 2.04→1.79 ms)** —
  같은 날 같은 트리 전/후 쌍 (전 3런 2057/2092/2161, 후 1822/1830/1905,
  매 런 own-v1 PASS). B-2 의 "합산 ~1.8s" 견적에 절대치로는 도달했으나
  당일 베이스라인이 B-2 시점 (2228) 보다 빨랐다 — **정직한 배율은
  당일 쌍의 -12.6%** (VM 변동성; B-2 기준 -19% 표기는 쓰지 않는다).
- GO-1 줌 셀-캐시: **surface CPU 8324.5 → 5600.8 ms (-32.7%)**, 커밋
  4f20ea9. GO-2 prepare dirty-skip: **prepare cpu 175.4 → 26.4 ms
  (-85%)** + light_final 26.0 → 3.9 ms (최종 prepare 도 스킵 수혜),
  no-op 증명 선행 + assert-빌드 실검증 게이트 동반, 커밋 c749125.
  GO-3 꼬리: **ser+sha 117.0 → 40.2 ms**, sha 페이즈 소멸 (스트리밍
  겹침), 커밋 b585121.
- REPLAY 도 동반 개선: 6963.5 (P2-5 confirm) → **5489.4 ms** 스팟 —
  GO-1 (surface 는 REPLAY 도 체인) + GO-2 (골든 이력 prepare 109회
  전량 스캔 → dirty-skip) + GO-3 의 합.
- 부산물 발견 2건: (a) **PT_TLS 가 이미 ~8.2MB** — 기본 8MB 스레드
  스택에서 차감되는 구조라 가용 스택 마진이 ~380KB 뿐 (§1 함정, 큰
  _Thread_local 신설 금지); (b) **"스폰 계단" 의 실체는 pthread_create

  자연 소멸하지 않는다, TLS 크기 함수다 (B-2 §3-11 의 "베어메탈 후"
  전제 수정 필요).
- DAG wall 616→563 ms 는 참고치만 — l09 cpu 가 런간 1788→2635 ms 로
  요동하는 VM 이라 (B-2 §5) DAG 절대치는 판정 지표가 아니다. GO-2 의
  판정 지표는 prepare cpu-sum 과 배리어 단독 구간 소멸.

## 1. GO-1 — surface 바이옴 줌 쿼트-셀 fiddle 캐시 (커밋 4f20ea9)

### 설계

- B-2 §2.1 관찰 그대로: `getFiddledDistance` 의 콘너별 오프셋 (fx,fy,fz)
  는 (zoom_seed, 콘너 정수좌표) 만의 순수 함수, 쿼리 블록은 (dx,dy,dz)
  분수만 기여한다. 한 쿼리의 8콘너는 셀 원점 (q0x,q0y,q0z) 로 결정 —
  **셀 단위 직접-매핑 캐시** (1024 엔트리, 태그 = seed+셀좌표)로 히트 시
  쿼리당 lcg 64회 (콘너당 8회 × 8) 가 3-double×8 조회로 붕괴한다.
- **값-불변 논거**: (a) 미스 경로는 종전 fiddled_distance 의 lcg/fiddle
  시퀀스를 함수 추출한 `corner_fiddle` — 연산·순서 동일. (b) 캐시는 그
  double 값을 그대로 저장/반환 (재계산·변환 없음). (c) 거리 합산식
  `(dz+fz)²+(dy+fy)²+(dx+fx)²` (좌결합) 과 `best_dist > d` 엄격 비교의
  i-순서는 hc_biome_zoom 본문에 종전 그대로 남는다. FMA 는 전역
  `-ffp-contract=off`, C 는 FP 재결합을 허용하지 않는다 → 비트 동일이
  구성으로 성립. 게이트: test_biome_zoom 골든 벡터 + 전 패리티 게이트.
- 콜사이트 불변 (hc_biome_view_get 내부) — surface (biome_col +
  ctx_biome memo) 뿐 아니라 09 측 (features/structures) 도 같이 수혜.

### 함정 — PT_TLS 는 이미 ~8.2 MB (실발화)

첫 구현은 `_Thread_local zoom_cell_t[2048]` (442KB) 였고 **chain_worker
가 즉사했다** (스택가드 SIGSEGV, `-fstack-clash-protection` 프로브에서).
원인: features_tree.c 의 P2-3 스레드-로컬 스크래치가 6.4MB 등 PT_TLS
가 이미 8,179,976B — glibc 는 정적 TLS 를 기본 8MB 스레드 스택에서
차감하므로 **가용 스택이 이미 ~380KB 뿐**이었다. 442KB 추가 = 즉사.

- 해법: bss 정적 풀 `g_zc_pool[192][1024]` + 스레드당 1회 relaxed 원자
  핸드아웃 (TLS 는 포인터/플래그 뿐). 슬롯은 소유 스레드 전용 (공유
  없음 — TSan 관측면은 카운터 뿐), 풀 소진 (프로세스당 192 스레드 초과)
  시 무캐시 폴백 — 동일 계산 경로라 값 동일. 안 쓴 슬롯은 제로 페이지
  (물리 0).
- **교훈 (다음 태스크용)**: 이 리포에서 큰 `_Thread_local` 은 금물.
  스레드-로컬 대용량은 풀+핸드아웃으로. PT_TLS 8.2MB vs 8MB 스택의
  마진은 이미 음수 직전이다 — features_tree 스크래치가 다음 후보.

### 실측

- surface CPU-sum 8324.5 → 5634.9 ms (**-32.3%**, 2.69 CPU-s). B-2 의
  줌 슬라이스 5.23 CPU-s (62.8%) 중 ~2.7 제거 — 잔여는 view_get·해시·
  탐색 8콘너 산술 + 룰 트리.
- chain wall 1293.4 → 1215.7 ms (-6.0%).

## 2. GO-2 — prepare dirty-skip (증명 선행)

### 증명 (구현 전 코드-수준; 게이트로 실검증)

**정리**: `hc_light_accum_prepare` 가 "마지막 재유도 이후 states[] 변경이
없는" in_r 청크의 `derive_geometry_chunk` 를 건너뛰어도 최종 상태
(registered/top/light/src_y)와 모든 fail-loud 검출은 종전과 동일하다.

**보조정리 1 (무변경 재유도 = no-op).** 청크 s 의 마지막 재유도 시점
T0 이후 s->chunk->states 가 불변이면, 시점 T1 의 derive_geometry_chunk(w,s)
는 상태를 바꾸지 않고 어떤 abort 도 유발하지 않는다.

- derive 의 **쓰기 집합은 s 자신의 비-공기 섹션 집합 nonair(s) 만의
  함수다**: 각 sec∈nonair(s) × 이웃 t(3×3) × dy∈±1 에 대해
  `t->registered |= bit(sec+dy)` 와 `t->top = max(t->top, sec+dy+1)`.
  states 불변 → nonair(s) 불변 (section_has_data 는 states 만 읽음).
- T0 의 재유도가 같은 (t, ns) 후보 전부에 비트를 이미 설정했고,
  registered/top 은 **단조 래치** (설정 경로는 derive 뿐, 클리어는
  hc_light_reset 뿐 — 코드 전수)다. 따라서 T1 에는 모든 후보 비트가
  이미 1, 모든 후보 top ≤ 현재 top → `if (!(t->registered & bit))`
  분기 미진입, top 갱신 없음.
- 신규-비트 분기 미진입 ⇒ pre_top 스냅샷은 읽히기만 하고 미사용,
  seeded-게이트 15-채움 memset 미실행, repeatFirstLayer die 검사
  미도달. 남는 abort 후보는 슬롯-부재 spill (이웃 attach 는 단조,
  T0 에 안 죽었으면 T1 에도 동일 분기) 뿐 → abort 없음. ∎
- **이웃 변경은 무관**: derive(s) 가 이웃에서 읽는 것 (registered/
  light 슬라이스/seeded/pre_top) 은 전부 신규-비트 분기 안이다. s 가
  무변경이면 분기 자체가 닫혀 있어 이웃이 어떻게 변했든 no-op 이
  유지된다 — **dirty 전파 (±1) 는 불필요** (B-2 판정표의 "±1 전파"
  는 보수적 추정이었다; 쓰기 집합이 자기-블록 함수라는 관찰로 해소).

**보조정리 2 (부분열 실행 등가).** prepare 는 슬롯 순서 순차 루프고,
스킵 대상은 항등 연산이므로 이를 제거한 부분열의 각 잔여 재유도가
관측하는 상태는 원 실행과 동일하다 (항등 원소 제거는 순차 합성 불변).
루프 말미의 check_contiguous 는 **종전 그대로 전역 스캔 유지** —
검출면 축소 없음 (스킵의 이득은 재유도의 states 전량 스캔 제거지
검사 제거가 아니다).

**보조정리 3 (dirty 채널 전수).** blk_dirty 가 "마지막 재유도 이후
states[] 변경"을 과소평가하지 않는다. 08 이후 청크 states[] 를 쓰는
채널 전수 (grep `states[...] =` 전 소스):

| 채널 | 신고 |
|---|---|
| hc_feat_set_block / _ks (features.c:151/188 — 데코·구조물·pp 전부의 초크포인트) | old≠id 일 때 on_block_write 발화 → **하네스 훅 5곳이 동결-창 필터 앞에서 mark_written** (아래) |
| ore 벌크 쓰기 (features.c:744, 바닐라 BulkSectionAccess 등가 — 훅 미경유) | 신고 불필요: ore_can_place 는 타깃 (stone 계열 비-공기) 매치에서만 쓰고 쓰는 값도 비-공기 → **비-공기→비-공기 뿐이라 nonair() 프로필 불변** → 보조정리 1 의 전제가 깨지지 않는다 |
| surface.c:82 / carvers.c:126 / chunk.c memset | 체인 스테이지 — 그 청크 08 (init_chunk 재유도) 이전이라 무관 |
| old==id 재기록 (pp_set_block 내부 no-op 포함) | states 불변 — 신고 불요 |

**동결-창이 함정이었다**: 라이트 훅은 08-완료 전 쓰기를 필터로
버리지만 (checkBlock/src_y 영구 미반영 — hc_light.h 헤더 실측 논거),
**섹션 등록은 현재-블록 재유도라 동결과 무관하게 라이브**다. 그래서
mark_written 은 5개 훅 (verify/full_region/free_region/bench replay/
bench free) 모두에서 **동결-창 필터 앞**에 넣었다. accum_write_ctx
내부에도 방어적 신고 (직접 호출자용).

**스레드 안전 (FREE)**: blk_dirty 접근은 (a) 쓰기 훅 — 그 블록 좌표는
이벤트 footprint ±1 안 = 셀 FIFO 가 직렬화, (b) flush/08 재유도 — 같은
footprint, (c) prepare — 전역 배리어 (완료 카운터 게이트, sched.c
mutex/cond HB). 공유-동시 접근 자체가 없다 — TSan 풀 스위트가 판정.

**게이트-실검증 (assert 빌드)**: `derive_assert_noop` — 스킵된 청크에
대해 "모든 후보 비트/top 이 이미 반영돼 있음" (보조정리 1 의 결론) 을
prepare 마다 실검사한다. mark_written 을 우회하는 states 변경 채널이
미래에 생기면 여기서 즉사한다 (ctest build/asan/tsan 전부 assert 온 —
full_region 109회 + free_region 25회 prepare 에서 전 골든 이력 검증됨).
release/bench (NDEBUG) 는 비용 0.

### 구현

- hc_light_chunk_t.blk_dirty (신설) — 설정: mark_written (훅 5곳) +
  accum_write_ctx; 해제: 그 청크의 재유도 3곳 (08 init / flush / prepare).
- hc_light_reset 이 geo_dirty/blk_dirty 를 초기화하게 수정 — geo_dirty
  잔존은 리셋-재사용 시 "첫 라이브 쓰기가 ctx dirty 목록 등재를 건너뜀"
  (재유도 누락) 채널이었다 (잠복 결함 동반 수리).
- prepare 의 스킵 이득 구조: 데코 이벤트의 라이트-유관 쓰기는 이벤트
  flush 가 이미 재유도+클리어하므로, prepare 에 남는 dirty 는 주로
  "동결-창 쓰기만 받은 청크 + 라이트-투명 쓰기만 받은 청크".

### 실측

- prepare cpu-sum **175.4 → 26.4 ms (-85%)** — 잔여는 dirty 부분집합
  재유도 + 전역 contiguity 스캔 (마스크 산술이라 염가). 배리어 단독
  실행 (매번 ~19스레드 정지 13→26ms) 이 ~2ms 대로 붕괴.
- light_final 26.0 → 3.9 ms — 최종 flush+prepare 의 prepare 도 스킵
  수혜 (예상 밖 보너스).
- DAG wall 616.5 → 563.2 ms (참고치 — 위 TL;DR l09 요동 캐벳).
- 스킵 이득의 구조: 데코 이벤트의 라이트-유관 쓰기는 이벤트 flush 가
  이미 재유도+클리어하므로, prepare 대상은 "동결-창/라이트-투명 쓰기만
  받은 청크" 로 준다 — 1461 전량 스캔 (청크당 24섹션×4096 states) 이
  수십 청크 수준으로.

## 3. GO-3 — serialize 파이프 정리 + sha 스트리밍

### 설계

- **core 스트리밍 SHA** (hc_sha256_ctx_t + init/update/final): 블록
  압축은 종전 디스패치 (sw/SHA-NI) 그대로, 원샷 hc_sha256 을 ctx 래퍼로
  재구성 — 경로가 하나라 기존 KAT/이중 배터리가 ctx 기계를 상시 검증.
  신규 게이트: test_sha256 §4 스트리밍-vs-원샷 배터리 (분할 위상 7종 ×
  길이 25종 = **175 동결** — 벤치 패턴 4B+가변 포함). 같은 바이트열 =
  같은 블록열이라 다이제스트 불변은 구성적.
- **concat 제거**: canonical 바이트열 ([4B BE idx][payload] × 1024,
  idx 순) 을 cat 버퍼 (192MB 할당 + 47MB memcpy) 없이 ctx 로 직접
  스트리밍. FREE 는 청크별 release 플래그를 메인이 idx 순 acquire 소비
  — sha 갱신이 워커 직렬화와 겹쳐 sha 페이즈가 소멸한다 (finalize 만
  잔존, ~µs). REPLAY 도 동일 스트리밍 (연접 memcpy 소멸 + 페이로드
  버퍼 1개 재사용).
- **스폰 계단의 실체와 해소**: pthread_create 가 이 프로세스에선
  ~2.5-3ms/스레드 — glibc 가 생성 시점에 **정적 TLS 블록 (PT_TLS
  ~8.2MB) 을 부모에서 제로화**하기 때문 (B-2 의 "3.3ms/스레드" 는 VM
  특성이 아니라 TLS 크기 함수였다; idle 마이크로벤치에서 소형-TLS
  바이너리는 20스레드 1.1ms). 워커는 DAG 직후 파킹-스폰하되, 생성
  대행 **헬퍼 스레드 1개**만 메인이 만들고 (B_ser_spawn 귀속) 나머지
  19+1 생성은 pp/lfinal 창 (~40ms) 과 실제로 겹친다. 늦게 생성된
  워커는 래치 플래그를 보고 대기 없이 통과. 첫 시도 (메인 직접 20
  스폰) 은 B_serialize 에 스폰 50-65ms 가 그대로 남아서 기각 — 계측
  귀속을 유지한 채(숨김 없음) 겹침으로 해소했다.
- 버킷 의미 변화 (summarize/waterfall 주의): FREE B_serialize = 파킹-
  스폰 소요 + 래치 해제→마지막 소비 (인터리브 sha 포함), B_sha256 =
  finalize 잔여 (~0). REPLAY 는 per-op 분리 계측이라 종전 의미 유지
  (serialize = 순수 nbt, sha256 = 스트림 갱신+finalize).

### 실측 (bench-o3 FREE, 20스레드)

- 꼬리 (serialize+sha256): **117.0 → ~44 ms** (95.4+21.6 → 42.2~45.9+0.0)
  — B-2 이론 플로어 (~35ms+꼬리) 대. 워터폴 실측: 워커 20 전원이

## 6. 시도했으나 기각/변경한 것

1. **GO-1 `_Thread_local zoom_cell_t[2048]` (442KB)** — chain_worker
   즉사 (스택가드 SIGSEGV). PT_TLS 가 이미 8,179,976B (features_tree
   6.4MB + lush 0.8MB) 라 기본 8MB 스택의 가용분이 ~380KB 뿐이었다.
   bss 정적 풀 (192슬롯) + 스레드당 relaxed 핸드아웃 + 소진 시 무캐시
   폴백으로 대체.
2. **GO-3 메인 직접 20-워커 파킹-스폰** — 파킹은 됐지만 스폰 루프
   자체가 50-65ms (pthread_create 부모-측 8.2MB TLS 제로화 ×20) 로
   B_serialize 에 잔존. 헬퍼-스포너 1개로 생성을 대행시켜 pp/lfinal
   창과 실겹침 (귀속은 유지 — 계측 사각으로 옮겨 숨기는 방식은 기각).
3. **GO-2 재유도별 즉시 box-검사** — flush 의 기존 국소화 패턴을
   따르려 했으나, prepare 는 다수 청크를 연속 재유도하므로 중간
   상태에서 일시적 마스크 갭 (뒤 재유도가 메울) 에 스퓨리어스 abort
   위험이 있다. 종전과 동일하게 **루프 말미 전역 check_contiguous 1회**
   로 확정 (비용은 마스크 산술뿐이라 스킵 이득과 무관).
4. **GO-1 10-bit fiddle 압축 저장** (엔트리 216→72B) — 히트 경로에
   /1024.0 실나눗셈 24회가 들어와 (reciprocal-math 금지) 이득 상쇄.
   double 그대로 저장 + 풀 방식으로 해소돼 불필요.
