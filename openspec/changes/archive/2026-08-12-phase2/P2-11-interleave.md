## 1. 설계 (커밋 e734995)

### 1.1 인터리브 구조

B-4 실증 (포트 가동률 9~10%, SMT co-run 1.52x) 의 함의: 체인 하나의 명령
수 (perlin 428 insn) 가 OoO 윈도우 (~ROB 448) 와 같은 자릿수라 하드웨어가
인접 호출을 겹치지 못한다 → 인터리브는 **leaf 함수 내부 문장 단위**여야
한다 (함수/노드 단위 교차는 하드웨어가 이미 하는 것 이상을 못 얻음).

- **dual 판 함수군**: wrap_x8_dual (always_inline — §2), perlin_x8_dual,
  octaves_x8_dual, normal_x8_dual, blended_x8_dual, x8_node2, x8_run2,
  엔트리 `hc_df_eval_stream_x8x2_avx512(g, stream, words, lanesA, vscA,
  ccA, lanesB, vscB, ccB)`. 각 함수는 단일 판의 문장을 A/B 접미사로
  복제·교차 — 사이드-바이-사이드 리뷰 면.
- **위임 규칙**: 제어 흐름이 스트림별로 갈리는 지점은 해당 스트림만 기존
  단일-스트림 함수로 위임 (위임 경로 = 원본 코드 그 자체). 지점: RC/IS
  레그 필요-집합 상이, blended over/under 편측, 포화/wrap 가드 실패.
  HC_CTR_X8_SPLIT 계수.
- **콜사이트 (noise_chunk.c)**: fill_slice y-그룹 (i, i+8) 페어 ×3 + 잔여
  단일 폴백 루프 + 스칼라 꼬리 (48 = 6그룹 → 페어 3, 잔여 0); select_cell
  iy 당 (ix=0 → A, ix=2 → B) 페어 (cell_width==4 에서 정확히 2그룹, 같은
  셀이라 cc 공유). density_cell 채움 순서 (iy 내림, ix, 레인) 는 A 8개 →
  B 8개 순 회수가 보존. 스트림 B scratch 는 신설 `nc->vscratch2`
  ([g->n][8], 64B — x8 시에만 할당), inv 브로드캐스트는 두 버퍼에.
- **카운터**: 기존 계수는 스트림당 1회 (단일 경로 2회 실행과 총계 동일 —
  §3.4 실증), 신설 3종 x8_dual (페어 콜) / x8_perlin2 (dual-커밋) /
  x8_split (위임 이벤트).

### 1.2 패리티 논증 (절대 조건)

- 각 스트림의 레인별 피연산자·결합 순서·선택 시맨틱은 단일 x8 경로와
  문자 그대로 동일 — 두 스트림은 값을 교환하지 않으므로 (수평 리덕션
  없음) 교차는 값-무관 기계 스케줄링이고 IEEE-754 결과는 스트림 단독
  실행과 비트 동일하다.
- 공유는 읽기 전용뿐: 그래프/스트림 워드, perm/GRAD 상주 레지스터
  (perm_load/grad_load 페어당 1회 — 로드 횟수는 값을 만들지 않음),
  옥타브 스칼라 (e/f/o/yscale — 원본에서도 전 레인 공통).
- perlin dual 의 카운터는 전 가드 통과 후에만 커밋 (+2) — 가드-위임 시
  단일 함수가 원본대로 계수해 이중/누락 없음.
- 판정면: df_x8 유닛 (scalar 이중 실행 9,376 비트 대조 — nc 공개 API
  경유라 dual 상시-온 경로가 그대로 판정됨) + parity_gate 풀-청크
  canonical + 3-way isa_equiv + FREE own-v1. 전부 PASS (§6).

## 4. K_fp 재판정 (조항 3) — 두 분모 병기

**조항 3 (≤3): 여전히 FAIL** — 어떤 방어-가능 포트-분모로도 3 미만 불가
(B-4 강건성 논증 승계; 분자만 1.3~1.4x 내려간 것).

**분모 2 — 체인 임계-경로 하한 (신설 병기, B-4 §7-4 예고)**: 결박이
체인임이 실증됐으므로 (포트 9~10%, SMT 1.34~1.52x) 단일-스트림 실측
cyc/node ≈ 노드당 임계-경로 지연으로 놓고 (bottom-up 산술과 정합: FP

## 5. 잔여 슬랙 판정

### 5.1 (a) 추가 인터리브 폭 — 기각 (레지스터-압력 논증, 실측 아님)

- **SMT co-run 후측정 (정직 기록)**: after solo 843.8ms, 동일코어 합산
  **1.395x** (크로스-코어 대조 1.982x); before 같은날 1.339x. 합산이
  ~1.0 으로 내려가지 **않았다** — 하드웨어 컨텍스트 (사설 아키텍처
  레지스터) 는 잔여 체인 슬랙을 여전히 회수한다.
- 그러나 소프트웨어 폭 확대의 자원은 다르다: 3-way 코너 단계 라이브 ≈
  6 공유 + 3×16 = **54 vs zmm32 (22 초과)** — 2-way 의 6 초과가 이미
  스필을 1.13 → 3.31/점으로 3배 올렸고 (§2), 초과분이 3.7배로 커지면
  코너/lerp 체인 값의 왕복 (store-forward ~7-8cyc) 이 옥타브당 수십 회
  강제 삽입된다. 이상 이득 (21.0 → 14.0 cyc/node, −7) 대비 스필 왕복
  증가분 (+5~10 cyc/node 오더) 이 같은 자릿수 → **순이득 소멸 대역**.
  구현·패리티-리뷰 면적 3배와 스필-재유입 리스크 (P2-10 회수 반납) 를
  합쳐 기각. 라벨: **논증 기각 — 실측 아님** (뒤집으려면 3-way 스팟
  구현이 필요하고, 그 실측 자체가 종결 증거가 된다).
- 소프트웨어 2-way 는 같은날 SMT 프록시의 ~97% (1.308 vs 1.339, micro
  wall) 를 이미 실현 — "SMT 가 증명한 회수 축" 명제는 소진됐다. 잔여
  회수력의 수단은 하드웨어 스레드 증설이며, 그 축은 B-3 "스레드 증설은
  축이 아니다" 판정 유지 (20T 는 이미 SMT 사용).

### 5.3 surface CPU +9.2% (16T) — 단일-스레드 캐시-상태 항 (2 가설 기각)

- **패드 대조군 (레이아웃 기각)**: before 트리에 vscratch2 와 동일한
  미사용 [g->n][8] 할당만 추가 (커밋 안 함, 측정 전용) → surface
  2335.1ms **불변** — arena 오프셋/캐시-셋 재배치 원인 기각.
- **1T 페어 (크로스-스레드 위상-간섭 기각 — 검증 워크플로 [HIGH])**:
  free1t 페어에서 surface 2296.4 → 2496.0ms (**+8.7%**) — 16T 델타의
  ~93% 가 스레드 중첩이 존재하지 않는 1T 에서 이미 발생한다. 최초
  해석 (멀티스레드 위상-간섭) 은 자기 원자료가 반증 — 폐기.
- **남는 유력 기전 (가설 라벨 — 미스 카운터 미측정)**: dual 실행의
  워킹셋 (vscratch+vscratch2 동시 터치 + 페어 병행 평가) 이 noise
  스테이지가 남기는 캐시 상태를 바꿔, 청크당 후속 surface 초입의 미스를
  늘린다 (per-op 코드·값은 무접촉 — canonical 불변). after 재현 페어
  (2545.9/919.6ms) 로 안정 확인.
- 절대 레벨 캐벳: B-4 의 같은-코드 16T surface 베이스는 2553.2ms — 오늘
  after (2549.8) 와 사실상 같고 오늘 before (2335.1) 가 그보다 −8.5%
  낮다. surface CPU-sum 의 일간 밴드가 커서 절대치 해석은 부적; 같은날
  페어 델타 (+9.2%) 만 판정에 쓴다.
- B-4 조항 2 투영: (b)-스코프 잔차를 오늘 after 로 재산출하면 2549.8/
  2316.5 = **+10.1%** — B-4 의 +9.3% 에서 거의 불변 (예측 c_i 도 같은
  1T 효과로 함께 움직이므로). 잔차 조항 (≤25%) 위협 없음. gen/chain
  wall 은 순이득이라 판정 무영향.

## 9. 함정 기록 (다음 태스크용)

- **test_sched 가 Release 트리에서 헛발 FAIL** — REPLAY 실행이
  `assert(hc_sched_run(...)==0)` 안에 있어 NDEBUG 에서 호출째 소거,
  직전 FREE 스탬프로 순차성 검사 실패 (claw Release 트리도 동일 재현 —

  넣지 말 것; `#undef NDEBUG` 없는 테스트 8개 파일은 스캔해 이 건만
  발견 (3dbef3e 수정).
- **vector_div PMU 카운트는 전/후 비교 불가** (93.1M → 17.6M): pow2
  나눗셈의 div→mul 정확-폴딩과 언롤-상수화가 인라인 문맥에 따라 달라짐
  — 값-보존 (게이트 3종이 증명) 이나 카운트는 컴파일러 선택의 산물.
  K_fp 플로어는 mul/add/sub 로만 (B-4 도 div 는 감도-병기).
- **fp_ops 이벤트명은 `vector_mul`** (scalar_mul 과 동형) — `vector_mult`
  는 없는 이벤트고 perf stat 이 -o 파일도 안 만들고 죽는다.
- **GCC 가 dual leaf 를 아웃라인하면 포인터-출력 왕복이 체인에 얹힌다**
  — wrap_x8_dual 은 always_inline 필수 (아웃라인 시 15 콜사이트 왕복).
  perlin_x8_dual 의 아웃라인은 의도 (RA 국소화, 왕복 2회/호출은 본체
  ~500cyc 대비 무시).
- **before 워크트리로 벤치를 돌리려면 gitignore 골든 (region-ref 등) 을
  심링크로 보충**해야 한다 — 없으면 bench 가 exit 0 으로 조용히 죽어
  빈 출력 파일이 남는다 (tail -1 캡처가 0바이트).
- 인접-스테이지 CPU-sum 이동 (surface +9.2%) 의 원인 판별은 **대조군
  2개가 다 필요하다**: 패드 대조군 (동일 할당·미사용 — 레이아웃 기각)
  + **1T 페어** (크로스-스레드 위상-간섭 기각). 이번에 최초 해석 (위상-
  간섭) 을 1T 페어가 반증했다 — 16T 델타의 93% 가 1T 에서 재현 (§5.3).
  arena 삽입은 후속 오프셋을 전부 밀기 때문에 패드 대조군 없이는
  레이아웃 룰렛과 구분 불가 (P2-2 코드-정렬 룰렛의 데이터 판).
- **프로파일 심볼-귀속은 커널-TU static 함수 전수 패턴으로** — 이름-부분
  grep (`x8_run|perlin_x8|…`) 이 before 의 아웃라인 wrap_x8 (0.96%) 을
  놓쳐 in-situ 판정치가 6% 어긋났었다 (검증 워크플로 [HIGH] 정정). TU
  확장은 단일-경로 함수의 인라이닝까지 재배치한다 — before/after 심볼
  집합이 같다고 가정하지 말 것.
- microbench 의 grand_mono 페어는 same-day 교차 실행이 판정 기준 —
  하루 사이 밴드 (B-4 44.45 vs 오늘 42.05 cyc/node, −5.4% — B-4 배치간
  밴드 ±3.5% 밖) 가 페어 간 이득과 같은 자릿수다. surface CPU-sum 은
  일간 이동이 더 커서 (−8.5%) 절대치 비교 자체가 부적.
